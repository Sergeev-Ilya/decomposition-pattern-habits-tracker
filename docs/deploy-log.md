# Ритм — журнал локального развёртывания

Дата проверки: 29 октября 2026. Target: `local`. Фактический SPA origin: **http://localhost:8880**.

Использован уже собранный и работающий Compose-стек; неизменённые образы повторно не собирались и не загружались. Домена, удалённого размещения, CI, брокера и S3 нет. Приложение оставлено работающим.

## Готовность и изоляция

Все шесть сервисов до и после перезапуска находятся в состоянии `running / healthy`: `frontend`, `api-gateway`, `auth-service`, `habits-service`, `auth-db`, `habits-db`. Внутренние HTTP-проверки `/health` у gateway и обоих доменных сервисов вернули 200; readiness frontend через SPA origin также вернула 200 и проверяет upstream и базы.

Единственная публикация порта на хост — `frontend`, `127.0.0.1:8880 → 80/tcp`. Gateway, сервисы и PostgreSQL не имеют опубликованных host-портов. Рабочие PostgreSQL 18 используют тома `ritm_auth_data` и `ritm_habits_data`, оба смонтированы на `/var/lib/postgresql`.

`backend/.env` игнорируется Git, имеет права `0600` и не изменился между снимками до/после перезапуска. Содержимое и секреты не выводились. Версии работающих контейнеров: Node.js `24.22.1`, PostgreSQL `18.6`, nginx `1.30.6`. Вспомогательный smoke запускался host Node.js `26.12.1`.

## Smoke через SPA origin

Все публичные HTTP-проверки выполнялись через `http://localhost:8880`, без обращения к отдельному host-порту gateway.

| Проверка | Результат |
|---|---|
| `GET /` | 200, SPA доступна |
| `GET /health` | 200, реальная readiness |
| `GET /api/auth/session` без cookie | 401, JSON error envelope |
| `GET /api/habits` без cookie | 401, JSON error envelope |
| `POST /internal/sessions/verify` | 404, JSON; внутренний маршрут закрыт |
| Неизвестный `/api/*` | 404, JSON, без SPA HTML |
| Регистрация синтетического аккаунта / вход / чтение сессии | 201 / 200 / 200 |
| Cookie сессии | HttpOnly, SameSite=Lax, Path=/, Max-Age=604800, host-only; HTTP-конфигурация localhost |
| Создание / выполнение / редактирование привычки | 201 / 200 / 200; история при редактировании сохранена |
| Календарь | Серверный `today=2026-10-29`, пояс аккаунта; 1 выполненная дата, знаменатель 31, процент `100 / 31` |
| Удаление собственной fixture-привычки | 204; последующее чтение — 404 |
| Выход для обеих сессий успешного прогона | 204, cookie очищена с прежними атрибутами; старые cookies затем дают 401 для session и habits |

Публичный маршрут текущего пользователя — `/api/auth/session`; `/api/auth/me` не входит в согласованный контракт. Поэтому использована эквивалентная проектная smoke-проверка, а не неверный для этого проекта default шаблона.

## Проверка сохранности после полного перезапуска

`scripts/persistence-smoke.mjs` создал отдельный синтетический аккаунт и привычку, отметил серверное сегодня, отредактировал название/описание и запомнил session, habit и calendar в памяти. Затем выполнил `docker compose restart` для всего текущего проекта и дождался health всех шести контейнеров и HTTP readiness.

Проверка `StartedAt` подтвердила, что перезапущен каждый из шести контейнеров. Имена и точки монтирования рабочих томов остались прежними; локальная конфигурация сохранилась побайтно и с правами `0600`. Cookie, выданная до перезапуска, продолжила возвращать тот же session. Привычка и полный календарь совпали со снимками до перезапуска, включая дату начала, описание, отметку, серию и месячный процент. Новый вход с исходными синтетическими credentials также прочитал тот же календарь.

Итоговый запуск завершился с **exit 0, 106 assertions passed**. Удалена только привычка этого fixture, затем отозваны обе его сессии. Синтетические аккаунты остаются; чужие данные и отдельные тестовые БД не затрагивались. Пароли, cookies и токены существовали только в памяти процесса. SQL-очистка рабочих баз, удаление томов и перезапись `.env` не выполнялись.

Первый прогон уже подтвердил сохранность, но остановился на проверке очистки logout-cookie: проверка ошибочно требовала только `Max-Age=0`, тогда как контракт также разрешает `Expires` в прошлом. Исправлена только проверка smoke-скрипта, после чего весь сценарий с перезапуском повторён успешно. Продуктовый код не менялся; deploy-проблем не обнаружено.

## Команды и передача на frontend tests

```sh
node --check scripts/start-local.mjs
node --check scripts/init-local-env.mjs
node --check scripts/persistence-smoke.mjs
node scripts/persistence-smoke.mjs
```

Smoke самостоятельно выполняет безопасные по отношению к секретам `docker compose ps --format json`, точечный `docker inspect` только mounts/StartedAt, внутренние health-запросы через `docker compose exec`, а также `docker compose restart`. Воспроизведение smoke временно перезапускает весь локальный стек.

Обычная команда запуска из корня остаётся `node scripts/start-local.mjs`. Она создаёт окружение только при его отсутствии, затем выполняет `docker compose up -d --build --wait --wait-timeout 120`; её исходник и синтаксис проверены, но повторная сборка готовых неизменённых образов на этой фазе не требовалась.

`state.baseUrl` установлен в `http://localhost:8880` только после успешных API smoke и проверки сохранности. Формальная фаза frontend E2E теперь **пройдена**; результаты и последующие frontend исправления приведены ниже и в [frontend-test-report.md](frontend-test-report.md).
