# Ритм — страницы и публичный API

Публичный контракт: [api-gateway.yaml](api-gateway.yaml). Все запросы frontend относительные к его origin; cookie передаётся через `credentials: 'same-origin'`. JWT не читается JavaScript и не хранится в Web Storage. Публичного `/api/auth/me` нет: текущий профиль возвращает `/api/auth/session`.

| Страница / действие | Запрос | Результат и действие frontend |
|---|---|---|
| `/register`: регистрация | `POST /api/auth/register` `{email,password,timeZone}` | `201 {user}`; перейти на `/login` с сообщением. `timeZone` определяется браузером; автоматического входа и писем нет. |
| `/login`: вход | `POST /api/auth/login` `{email,password}` | `200 {user,expiresAt}` и HttpOnly-cookie; перейти на сохранённый внутренний URL либо `/`. Сохранить выбранный месяц в return-to. |
| Первое открытие/перезагрузка личной страницы | `GET /api/auth/session` | `200 {user,expiresAt}`; только после проверки загружать привычки. При 401 перейти на вход, при 503 показать ошибку и повтор, не ложный logout. |
| Любая личная страница: выход | `POST /api/auth/logout` без тела | `204` после отзыва и очистки cookie; очистить личное состояние, перейти на вход. При 503 не сообщать об успешном выходе. |
| `/`: список/повтор загрузки | `GET /api/habits` | `{habits,today,timeZone,limit:25}`; пустой массив — пустой список. Ошибка загрузки не подменяется пустым списком. |
| `/`: создать привычку | `POST /api/habits` `{name,description?}` | `201 {habit,today,timeZone}`; закрыть форму и обновить список. `409 HABIT_LIMIT_REACHED` оставляет форму с объяснением. |
| `/`: сегодняшняя кнопка | `PUT /api/habits/{id}/completions/{today}` `{completed: !todayCompleted}` | `200 {habit,date,completed,today,timeZone}`; использовать подтверждённый summary и обновить список. Не вызывать серверный toggle. |
| `/habits/:habitId`: первичная сводка | `GET /api/habits/{id}` | `{habit,today,timeZone}`; нужны startDate/серверный месяц для нормализации query. 404 одинаков для чужой и неизвестной привычки. |
| Календарь/переход между месяцами | `GET /api/habits/{id}/calendar?month=YYYY-MM` | `{habit,month,completedDates,completedCount,daysInMonth,completionPercent,editableFrom,editableTo,today,timeZone}`. Невалидный query страницы заменить текущим месяцем; запросить нормализованный месяц. |
| Календарь: установить/снять дату | `PUT /api/habits/{id}/completions/{date}` `{completed:boolean}` | Применить подтверждённый summary, затем перечитать выбранный календарь. При 400 `DATE_NOT_EDITABLE` обновить календарь и окно; ложную отметку не оставлять. |
| Список/календарь: редактировать | `PATCH /api/habits/{id}` `{name?,description?}` | `200 {habit,today,timeZone}`; обновить название/описание, сохранить историю. Требуется хотя бы одно поле. |
| Список/календарь: удалить после диалога | `DELETE /api/habits/{id}` без тела | `204`; обновить список, со страницы удалённой привычки перейти на `/`. Отмена диалога не отправляет запрос. |
| Проверка готовности локального стека | `GET /health` через origin frontend | Gateway проверяет оба сервиса и их БД; `200` только если оба готовы, иначе `503`. |

## Правила адаптации согласованного прототипа

- `HabitSummary`: `id,name,description,startDate,createdAt,updatedAt,currentStreak,todayCompleted,recentCompletedDates`. Рабочий frontend использует серверные `currentStreak` и `todayCompleted`, не пересчитывает их из ограниченного массива дат. Полной истории в списке нет.
- `recentCompletedDates` содержит только `[today−6,today]` — семь дат для обзора. Редактируемое окно календаря шире: восемь дат `[max(startDate,today−7),today]`. Отсутствие даты в recent-массиве вне его диапазона не означает отсутствие выполнения в истории.
- Для календаря `completedDates` относится только к выбранному месяцу. Серия в `habit` всегда текущая. Процент берётся с сервера, отображается с одним десятичным знаком; знаменатель — весь месяц.
- После успешной записи перечитывать нужные данные; не заменять их mock-fallback. На смене суток перечитать серверный контекст. Клиентские часы не разрешают изменение даты.
- Создание/редактирование проверяют технические пределы: название после trim 1–120 Unicode-кодовых точек, описание — строка после trim до 2000, по умолчанию `''`, не `null`. Пароль регистрации 8–128 кодовых точек; без обязательных классов символов и без trim. Backend повторяет проверки.
- На запросе сохранения блокировать повторную отправку этого действия. При ошибке форма сохраняет введённые значения, отметка возвращается к последнему подтверждённому состоянию. Автоматических повторов POST-создания нет.
- При 401 из защищённого API убрать личные данные и перейти на вход с безопасным return-to. При 503 оставить сессию неподтверждённой/сохранить ранее подтверждённый экран с ошибкой и возможностью повтора; не представлять сбой как отсутствие данных или успешное сохранение. На старте до проверки сессии личные данные не показывать.
- `404 HABIT_NOT_FOUND`: один экран «Привычка не найдена», без раскрытия владельца/названия. Неизвестный маршрут frontend обрабатывает собственной страницей 404.

## Origin, маршрутизация и ошибки

Браузер сам ставит `Origin` в изменяющих same-origin запросах. Конфигурация `APP_ORIGIN` должна точно совпадать с фактическим frontend URL, включая порт; `localhost` и `127.0.0.1` не взаимозаменяются. Curl/интеграционные тесты явно передают тот же `Origin`. Непустое тело — `Content-Type: application/json`, максимум 16 KiB. Без/чужой Origin — 403; неизвестные поля JSON отклоняются.

Frontend reverse proxy сохраняет `/api/...` при передаче на `api-gateway:8080`, а `/health` передаёт на gateway readiness. Статический `200` из исходного nginx-шаблона для `/health` должен быть заменён proxy. `/api/*` и `/internal/*` не получают SPA HTML; внутренний `POST /internal/sessions/verify` никогда не публикуется. Gateway пересылает только пути `/api/auth/` на `auth-service:3000` и `/api/habits` с границей сегмента на `habits-service:3000`; произвольных upstream от клиента нет.

Каждая ошибка: `{error:{code,message,details?},requestId}`. `requestId` — UUID gateway, также в `X-Request-Id`; детали содержат только безопасные ошибки полей. Cookie/пароли/токены/секреты/SQL не логируются. Origin — 403; неверный ввод/месяц/дата — 400; лимит/занятый email — 409; чужая привычка — 404; отсутствующая/отозванная сессия — 401; недоступный/некорректный/просрочивший timeout upstream или БД — 503. Неверные данные входа — 401 `INVALID_CREDENTIALS`.

Gateway сохраняет отдельные `Set-Cookie`, задаёт новый UUID запроса и не доверяет клиентским `X-User-*`, `X-Service-Key` и `Authorization`. Таймаут upstream — 5 секунд, readiness-запросов — 2 секунды; автоматических повторов нет. Внутренний habits → auth запрос использует другой маршрут и service-key по [auth-контракту](auth-service/api.yaml), без доступа из браузера.
