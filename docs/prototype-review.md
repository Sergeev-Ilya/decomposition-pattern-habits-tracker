# Ритм — просмотр прототипа

Статус: **прототип согласован пользователем** ответом «Прототип подтверждаю». Подготовка и просмотр завершены.

Исторический адрес прототипа: http://127.0.0.1:5173/. Его временный сервер остановлен после завершения рабочей версии; прототип можно повторно запустить по README. Демо-вход `demo@ritm.app` / `demo1234` относится только к прототипу. Рабочее приложение доступно на http://localhost:8880 и использует собственную регистрацию.

Исходники и инструкции запуска: [prototype/README.md](../prototype/README.md). Реализованы четыре страницы и три диалога из [спецификации страниц](pages-spec.md).

## Проверено

- `npm run build`: TypeScript и Vite, exit 0 после окончательных исправлений.
- `npm audit fix`: совместимые обновления зависимостей шаблона; итоговый аудит — 0 уязвимостей.
- HTTP главной страницы: 200; стили Tailwind видны в браузере.
- Демо-вход, регистрация mock-аккаунта, вход в него и пустой список привычек.
- Установка и отмена сегодняшней отметки, изменение серии.
- Установка отметки на D−7: серия и месячные показатели пересчитываются. Более ранние и будущие даты недоступны.
- История предыдущего месяца: выполненные дни отображаются; процент использует полное число календарных дней месяца.
- Восемь проверок календарной логики: серия до вчера, серия с сегодня, пропуск вчера, разрыв серии, границы недельного окна, дата создания, високосный февраль и смена года.
- Создание, редактирование названия/описания, подтверждение удаления и возврат фокуса после удаления.
- Прямой URL привычки направляет гостя на вход; после входа восстанавливаются привычка и выбранный месяц.
- Интерфейс просмотрен на компьютере и в мобильном viewport 390×844. На мобильном списке и календаре нет горизонтального переполнения; email доступен внизу страницы.
- После итоговой проверки в браузере нет сообщений console error/warn.

## Границы прототипа

Это интерактивный UI на демонстрационных данных. Аккаунты и изменения хранятся в памяти открытой страницы и сбрасываются при перезагрузке. API, постоянная база данных и настоящая авторизация будут реализованы на следующих этапах. Для регистрации в прототипе используйте вымышленные данные.

Проверки прототипа не заменяют backend-тесты и итоговые Playwright E2E. Эти проверки впоследствии выполнены для рабочей версии: [backend](backend-test-report.md), [frontend](frontend-test-report.md). `approvals.prototype` установлен в `true` по ответу пользователя.

После прототипа согласовано [локальное размещение](deployment-plan.md), выполнены архитектура и реализация. Инструкция рабочей версии: [локальный запуск](run-local.md).
