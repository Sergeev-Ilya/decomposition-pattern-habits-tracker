## Покрытие

Компонентные тесты используют настоящий AppProvider и страницы с mock HTTP только внутри Vitest. Проверены: скрытие личных данных до проверки сессии; различение 401 и 503; повтор после 503; сохранение подтверждённого списка при временном сбое; блокировка повторного входа и сохранение введённых данных при ошибке; ограничения регистрации и передача часового пояса; отсутствие автоматического входа после регистрации; поздний ответ начальной сессии после нового входа; очистка профиля/привычек/модального состояния при защищённом 401 и отбрасывание позднего списка. Формы привычек проверяют whitespace-имя, busy, ошибку API с сохранением значений и успешный повтор. Календарь проверяет задержанный ответ после смены месяца, текущую серию отдельно от прошлого месяца и запрет старых дат. Отдельные регрессии проверяют ожидание обновлённого календаря, Tab/Shift+Tab и возврат фокуса после cancel.

Шесть реальных E2E-сценариев покрывают:

1. `/login`, `/register`, перенаправление гостя с `/`, валидацию пароля, регистрацию и вход через UI, пустой список, выход, HttpOnly cookie, отсутствие Web Storage; авторизованный пользователь не остаётся на auth-страницах.
2. `/` → создание в UI → список → `/habits/:id`; отметка сегодня, сохранение после reload, отмена и повторная отметка в календаре; независимую проверку полного числа дней месяца и `100/days` с отображением одного знака; будущие и предшествующие созданию даты disabled; редактирование без потери истории; безопасную отмену удаления, подтверждённое удаление и последующий серверный 404.
3. Прямой защищённый URL с выбранным месяцем; нормализацию malformed/нулевого/некорректного/слишком раннего/будущего месяца; выход и возврат после входа на запрошенную привычку и месяц.
4. Неизвестный frontend route для гостя и пользователя; неизвестную привычку с нейтральным 404.
5. Отзыв реальной браузерной сессии через публичный API, повторное предъявление сохранённой отозванной cookie, защищённый 401, немедленное удаление личного содержимого и отсутствие его после reload.
6. Viewport 390×844: отсутствие горизонтального overflow в списке, диалоге, календаре и входе; открытие клавиатурой, фокус внутри модального окна при Tab, Escape, возврат к открывшей кнопке, отсутствие сохранения при отмене.

Во всех браузерных сценариях проверяется отсутствие pageerror и неожиданных console.error. Ожидаемые HTTP 401 при проверке гостя/отозванной сессии и 404 для неизвестной привычки учитываются отдельно от ошибок JavaScript.

## Исправления и итерации

Выполнены **3 продуктовых цикла исправлений**:

1. `HabitPage`: после успешной записи busy мог завершиться раньше обновления календаря; повторное нажатие использовало старый completedDates. Даты и обработчик записи теперь заблокированы на loading и при ошибке snapshot до успешного обновления. Регрессия проверяет, что следующий запрос после подтверждения снимает отметку.
2. `HabitDialog`: нативный dialog в Chrome позволял Tab перейти за пределы документа. Добавлен явный wrap Tab/Shift+Tab между доступными элементами.
3. `HabitDialog`: при размонтировании нативное закрытие не возвращало фокус. Открывающий элемент сохраняется до монтирования и восстанавливается в cleanup, если ещё существует. Существующий отложенный фокус на следующей привычке/создании после удаления сохранён и имеет приоритет.

После каждого изменения production frontend пересобран до соответствующего E2E. При первой сборке обычный Compose `up --build frontend` также пересоздал зависимые сервисы из cached images; БД оставались запущены, конфигурация и тома сохранены. Последующие сборки использовали `--no-deps` и обновляли только frontend. Полный persistence restart smoke повторно не запускался.

Всего выполнены 4 реальных полных запуска E2E: 4/6, 5/6, 5/6, **6/6**. Первые неуспехи включали исправленные ожидания harness (сырой процент API против округлённого UI; допустимый начальный фокус внутри dialog) и два обнаруженных нарушения фокуса. Дополнительная начальная попытка Chrome в sandbox завершилась EPERM до выполнения сценариев; последующие CLI запущены с разрешённой эскалацией. Неправильные селекторы/вызов cancel в новых unit-тестах исправлены в тестах. Условия утверждённой спецификации не ослаблялись. Только окончательные успешные CLI учитываются в gate.

## Воспроизведение и доказательства

```sh
npm test

npm audit --json
```

