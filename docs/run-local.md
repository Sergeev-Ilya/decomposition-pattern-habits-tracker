# Ритм — локальный запуск

Требуются Docker Desktop с работающим движком и Node.js 24 или новее для вспомогательного скрипта.

Из корня репозитория:

```bash
node scripts/start-local.mjs
```

Скрипт создаёт игнорируемый `backend/.env` с независимыми случайными секретами и правами 0600, если файла ещё нет. При повторном запуске конфигурация сохраняется. Затем Compose собирает приложение и ждёт готовности сервисов. Стандартный адрес — **http://localhost:8880**. Зарегистрируйте аккаунт по email и паролю; публичного демо-аккаунта в рабочей версии нет.

Можно подготовить конфигурацию отдельно:

```bash
node scripts/init-local-env.mjs
cd backend
docker compose up -d --build --wait --wait-timeout 120
```

Внешний порт опубликован только на loopback. API, PostgreSQL и внутренний session-verify доступны только в сети Compose. `/api/*` и `/health` обслуживаются через frontend/reverse proxy. В `backend/.env` адрес APP_ORIGIN и FRONTEND_PORT должны соответствовать друг другу; localhost и 127.0.0.1 для cookie и Origin считаются разными адресами.

Остановка с сохранением данных:

```bash
cd backend
docker compose stop
```

Повторный запуск выполняется той же командой `node scripts/start-local.mjs` из корня. Именованные тома `ritm_auth_data` и `ritm_habits_data` сохраняют аккаунты и историю между перезапусками. Для PostgreSQL 18 тома смонтированы на `/var/lib/postgresql`, согласно [официальному описанию образа](https://hub.docker.com/_/postgres). Обычные команды запуска и остановки не удаляют тома. Сохраняйте также `backend/.env`: в нём находятся настройки доступа и ключи активных сессий.

Размещение локальное, без домена, CI, брокера сообщений и S3. Проверки backend используют отдельные временные базы, а не рабочие тома приложения.
