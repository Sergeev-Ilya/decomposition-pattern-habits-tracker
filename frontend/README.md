# Ритм — frontend

Рабочий React + TypeScript + Vite frontend сохраняет согласованное оформление прототипа и обращается к живому API. Tailwind CSS v4 подключён через `@tailwindcss/vite`. Исходный `prototype/` остаётся отдельным артефактом согласования.

## Локальный запуск

Полный стек запускается из корня репозитория:

```sh
node scripts/start-local.mjs
```

После готовности сервисов приложение доступно по **http://localhost:8880**. Используйте именно `localhost`: настроенный backend `APP_ORIGIN` должен точно совпадать со схемой, именем хоста и портом браузера. Внешние CORS-origin не разрешаются. Секреты остаются только в игнорируемом `backend/.env`; они не передаются в frontend.

Обновление frontend при уже работающем backend:

```sh
cd backend
docker compose up -d --build --wait --wait-timeout 120 frontend
```

Dockerfile собирает приложение в Node 24 и раздаёт результат через `nginx:stable-alpine`. Nginx сохраняет URI `/api/*` при передаче на `api-gateway:8080`, закрывает внутренние пути через gateway JSON 404 и использует Docker DNS для повторного разрешения адреса gateway. `/health` проксирует readiness gateway и обоих сервисов с БД. Страницы приложения получают SPA fallback; неизвестные API и internal пути не получают HTML приложения.

## Разработка

Сначала запустите полный стек на `localhost:8880`, затем:

```sh
cd frontend
npm ci
npm run dev
```

Vite по умолчанию выбирает порт 5173 либо следующий свободный. Браузер по-прежнему вызывает относительные `/api/*`; dev proxy пересылает их и `/health` на `http://localhost:8880`. Только этот локальный dev proxy переписывает Origin на origin целевого frontend, поскольку backend строго проверяет `APP_ORIGIN`. Gateway не опубликован отдельным портом на хосте. При ином локальном адресе стека задайте `DEV_PROXY_TARGET=http://localhost:PORT` перед запуском Vite и согласуйте backend `APP_ORIGIN` с адресом стека. Cookie остаётся HttpOnly и same-origin; CORS и серверная проверка Origin не ослабляются.

```sh
npm run build
```

Команда проверяет TypeScript и создаёт `dist/`. `npm run preview` показывает сборку без API proxy; для полной проверки используйте Docker frontend или Vite dev proxy.

## Страницы и live API

| Страница / действие | API | Поведение |
|---|---|---|
| `/register` | `POST /api/auth/register` | `{email,password,timeZone}`; после 201 перейти на вход. Пояс определяет браузер, восстановления пароля нет. |
| `/login` | `POST /api/auth/login` | Cookie-сессия; переход на безопасный сохранённый внутренний URL с выбранным месяцем. |
| Первое открытие / перезагрузка | `GET /api/auth/session` | Проверить сессию до показа личных данных; loading, 401 и ошибка сервиса различаются. |
| Выход | `POST /api/auth/logout` | Дождаться отзыва, очистить личное состояние. Ошибка сервиса не выдаётся за успешный выход. |
| `/` | `GET /api/habits` | Серверные серии, todayCompleted, семь последних дат, серверные today и пояс. |
| Создание / редактирование / удаление | `POST /api/habits`, `PATCH /api/habits/:id`, `DELETE /api/habits/:id` | Три модальных диалога; подтверждение удаления истории, сохранение формы при ошибке, обновление списка и лимита 25. |
| Сегодняшняя отметка | `PUT /api/habits/:id/completions/:date` | Идемпотентное желаемое `{completed:boolean}`; показывать подтверждённый summary. |
| `/habits/:habitId?month=YYYY-MM` | `GET /api/habits/:id`, `GET /api/habits/:id/calendar?month=YYYY-MM` | Серверные месячные отметки, числитель, полный знаменатель, процент и границы редактирования. |
| Календарная отметка | `PUT /api/habits/:id/completions/:date` | Подтвердить summary и перечитать выбранный календарь. |
| Готовность | `GET /health` | Реальная readiness всех upstream, без статического успешного ответа. |

`src/api/types.ts` описывает публичные DTO, `src/api/client.ts` — относительный fetch с `credentials: 'same-origin'` и типизированной ошибкой общего envelope. Токены и пароли не записываются в Web Storage; профиль пользователя не содержит пароль. Сессия сохраняется серверной HttpOnly-cookie после обновления страницы. При защищённом 401 личное состояние очищается; 503 сохраняет подтверждённый экран и предлагает повторить запрос.

Начальная проверка сессии отменяется перед входом. Epoch сессии и последовательность запросов списка не позволяют поздним ответам восстанавливать данные после выхода; запросы календаря отменяются при смене маршрута/месяца. Переходы месяцев используют query и историю браузера. Некорректный либо недоступный месяц заменяется текущим серверным месяцем. Серверные данные обновляются при фокусе окна и каждые 30 секунд, включая смену суток; даты календаря вычисляются UTC calendar helpers без разницы миллисекунд через DST.

Недельный обзор использует только `[D−6,D]`; окно редактирования приходит с сервера и включает `[max(startDate,D−7),D]`. Серия не вычисляется по ограниченным recent-датам. Нейтральная иконка листа и цвета по идентификатору относятся только к оформлению. Демо-аккаунта, demo-входа и mock fallback в рабочем frontend нет.

## Автоматические тесты

Требуется Node >=24 и запущенный production стек. Из `frontend/`:

```sh
npm test
PLAYWRIGHT_BASE_URL=http://localhost:8880 npm run test:e2e
```

Vitest + Testing Library используют mock HTTP только в компонентных тестах. Playwright обращается к реальному `state.baseUrl`; конфигурация отклоняет отсутствующий или отличающийся полный origin. Браузер — уже установленный Google Chrome (`channel: chrome`), headless, отдельные контексты, один worker, без retries. Установка браузера не нужна.

E2E создаёт уникальные синтетические аккаунты; после сценариев через публичный API удаляет только их привычки и завершает сессии. Аккаунты могут оставаться в БД. Результаты последнего запуска находятся в игнорируемой `test-results/`.
