# Ритм — habits-service

Express + TypeScript + PostgreSQL. Сервис владеет привычками, выполнениями, текущими сериями и месячной статистикой. Контракт — [`docs/habits-service/api.yaml`](../../docs/habits-service/api.yaml), транзакции и схема — [`db.md`](../../docs/habits-service/db.md).

## Запуск

Требуется Node.js 24+, собственная PostgreSQL-база и работающий auth-service. Скопируйте `.env.example` в локальный игнорируемый `.env` и задайте реальные локальные значения. `JWT_SECRET` и `INTERNAL_SERVICE_KEY` должны совпадать с соответствующими значениями auth-service, быть различными и содержать не менее 32 байт. Примеры `REPLACE_WITH_*` не принимаются. `APP_ORIGIN` — точный origin интерфейса, включая порт. `AUTH_SERVICE_URL` — доверенный origin внутреннего auth-service.

```bash
npm install
npm run build
npm start
```

Перед началом HTTP-прослушивания `start` применяет версионированные SQL-миграции. Повторный запуск не очищает данные. Отдельная команда миграций: `npm run migrate`. `/health` проверяет собственную БД. Dockerfile использует Node 24, выполняет сборку и запускает runtime от пользователя `node`.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Готовность сервиса и БД |
| GET / POST | `/api/habits` | Список / создание |
| GET / PATCH / DELETE | `/api/habits/:habitId` | Чтение / редактирование / удаление |
| GET | `/api/habits/:habitId/calendar?month=YYYY-MM` | Календарь и статистика месяца |
| PUT | `/api/habits/:habitId/completions/:date` | Явное `{completed:true/false}`, идемпотентно |

Каждый защищённый запрос проверяет единственную cookie `ritm_session`, подписанный JWT HS256 и активную сессию через `POST /internal/sessions/verify` auth-service. Внутренний HTTP-запрос имеет отдельный service-key и двухсекундный timeout. Подтверждённые user/session IDs сверяются с JWT; часовой пояс берётся из ответа auth-service. Отзыв сессии даёт 401, сбой проверки — 503. Данные чужого владельца не раскрываются и дают 404.

Изменяющие запросы требуют точный `Origin=APP_ORIGIN`. Непустое тело — JSON до 16 KiB; неизвестные поля, неверные типы, невозможные даты и NUL в тексте отклоняются. Пароли, cookie, JWT, ключи и SQL-ошибки не логируются и не возвращаются в ошибках. Браузерные CORS-origin не разрешаются.

Лимит 25 защищён блокировкой локальной строки владельца. Изменение отметки блокирует привычку и повторно определяет календарное «сегодня» после ожидания блокировки. Разрешены `[max(startDate,D−7),D]`, включая оба края. Каскадное удаление истории и освобождение слота коммитятся одной транзакцией. Серии и проценты вычисляются из сохранённых выполнений; знаменатель — все дни выбранного месяца. Клиент получает ограниченные DTO, а не всю многолетнюю историю.

## Проверки

`npm run build` проверяет TypeScript. Интеграционные тесты требуют **отдельную временную** базу с именем `ritm_habits_test` на `localhost` или `127.0.0.1`; остальные адреса/имена отклоняются до выполнения очищающих fixtures.

```bash
TEST_DATABASE_URL=postgresql://TEST_USER:TEST_PASSWORD@127.0.0.1:55432/ritm_habits_test npm test
```

Набор из 27 проверок выполнен на PostgreSQL 18.6: CRUD, первая конкурентная запись владельца, конкурентное достижение 25, освобождение слота, идемпотентность и no-op timestamps, границы дат/создания, серии с восстановлением пропуска, месячная история и полный знаменатель, високосный февраль, граница года, DST, повторная проверка даты после row lock, сохранение/каскадное удаление истории, изоляция, Unicode/JSON/Origin-валидация, JWT и отзыв, недоступность/невалидный ответ auth-service, readiness и конфигурация.

Тестовые часы внедряются через `createApp` в серверном коде. Публичного API для произвольной подмены даты, владельца или часового пояса нет.
