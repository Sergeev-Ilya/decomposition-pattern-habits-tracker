# Ритм — auth-service

Express/TypeScript + PostgreSQL, JWT HS256 в HttpOnly-cookie и отзывные сессии. Контракты: `docs/auth-service/api.yaml` и `db.md`.

## Запуск

Нужен Node.js 24+ и отдельная PostgreSQL 15+. Установите зависимости `npm ci`, задайте переменные из `.env.example`, выполните `npm run build`, затем `npm start`. Сервер выполняет версионированные миграции перед открытием порта. `npm run migrate` позволяет применить их отдельно. Повторный запуск не очищает данные и не создаёт demo-аккаунт.

`APP_ORIGIN` должен точно совпадать с origin браузера. `JWT_SECRET` и `INTERNAL_SERVICE_KEY` — разные случайные значения не короче 32 байт; в репозитории сохраняются только placeholders. Их необходимо сохранять между перезапусками. `COOKIE_SECURE=false` допускается лишь для HTTP на localhost/127.0.0.1/[::1]; для внешнего размещения нужны HTTPS и `COOKIE_SECURE=true`. Файл `.env` игнорируется Git.

## API

| Метод и путь | Назначение |
|---|---|
| `GET /health` | Готовность собственной БД после миграций |
| `POST /api/auth/register` | Email, пароль 8–128 символов, IANA `timeZone`; создание без автоматического входа |
| `POST /api/auth/login` | Вход; cookie `ritm_session` на 7 суток |
| `GET /api/auth/session` | Профиль и срок активной сессии |
| `POST /api/auth/logout` | Отзыв текущей сессии и очистка cookie |
| `POST /internal/sessions/verify` | Внутренняя проверка `{token}`, требует `X-Service-Key` |

Публичные изменяющие запросы требуют точный `Origin`; непустое тело — JSON до 16 KiB. Внутренняя проверка использует отдельный service-key, а не Origin. JWT, пароль, cookie и ключи не включаются в JSON/логи. `/internal/*` не должен публиковаться gateway.

Пароли хешируются встроенным scrypt (`N=131072,r=8,p=1`, соль 16 байт, результат 64 байта, maxmem 256 MiB). Email нормализуется trim/lowercase; пароли не нормализуются. Активность сессии проверяется по PostgreSQL на каждом запросе, поэтому повторное использование JWT после выхода отклоняется. Недоступность БД — 503, а не успешный выход или 401.

## Тесты

Интеграционные тесты используют **отдельную disposable БД**, имя которой оканчивается `_test`; рабочую БД они не принимают. Задайте `TEST_DATABASE_URL`, затем `npm test`. Миграции запускаются тестами; таблицы аккаунтов тестовой БД очищаются перед сценариями. Тесты выполняются последовательно с настоящими SQL-ограничениями и scrypt-профилем.

Фабрика `createApp({pool,config,clock})` позволяет внедрить отдельный пул и серверные часы без глобального подключения при импорте. Docker-образ использует Node 24 Alpine и пользователя `node`.
